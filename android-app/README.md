# NFC Keycard (Android)

แอป Android แบบเนทีฟ (Kotlin) มี 2 วิธีเข้าถึงประตู:

1. **แตะบัตร NFC keycard ที่มีอยู่แล้ว** กับด้านหลังโทรศัพท์ — แอปอ่าน UID แล้วส่งไปตรวจสอบสิทธิ์กับ API
2. **กดปุ่ม "เปิดประตู"** ในแอป — เปิดประตูทันทีโดยไม่ต้องใช้บัตร

> **ทำไมไม่ปลอมมือถือเป็นบัตร (HCE)?** เครื่องอ่านประตูส่วนใหญ่ที่ใช้ MIFARE Classic อ่านแค่ UID
> ที่ระดับ ISO14443-3 (anti-collision) เท่านั้น ซึ่ง Android ไม่เปิดให้แอปปลอม UID ของ HCE ให้ตรงกับ
> บัตรจริงได้ (ข้อจำกัดด้านความปลอดภัยของแพลตฟอร์ม ไม่ใช่ข้อจำกัดของแอปนี้) การเปิดประตูผ่านปุ่มที่ยิง
> API ตรงๆ จึงเป็นทางเดียวที่ทำงานได้จริงกับเครื่องอ่านประเภทนี้

## วิธีใช้งาน

1. เปิดโปรเจกต์ `android-app/` ด้วย Android Studio (Hedgehog ขึ้นไป) — Android Studio จะสร้าง
   Gradle wrapper ให้อัตโนมัติเมื่อ sync โปรเจกต์ครั้งแรก (โปรเจกต์นี้ยังไม่มี `gradlew` เพราะ
   สภาพแวดล้อมที่ใช้สร้างโค้ดไม่มีสิทธิ์เข้าถึงอินเทอร์เน็ตแบบเต็มสำหรับดาวน์โหลด Gradle
   distribution — Android Studio หรือคำสั่ง `gradle wrapper` บนเครื่องคุณจะจัดการให้)
2. เปิดแอปบนมือถือ Android (จริง ไม่ใช่ emulator เพราะต้องใช้ฮาร์ดแวร์ NFC) แล้วกดปุ่มตั้งค่า
   (ไอคอนรูปเฟือง มุมขวาบน) เพื่อกรอก:
   - **API Endpoint สำหรับตรวจสอบสิทธิ์**: URL ของ API ตรวจสอบสิทธิ์เมื่อแตะบัตร
   - **API Endpoint สำหรับเปิดประตู**: URL ของ API ที่สั่งเปิดประตูโดยตรง (ไม่บังคับ — ถ้าไม่กรอก
     ปุ่ม "เปิดประตู" จะแจ้งเตือนให้ไปตั้งค่าก่อน)
   - **API Key** (ถ้า API ต้องใช้ ใช้ร่วมกันทั้งสอง endpoint)
3. กลับไปหน้าหลัก แล้วเลือกได้สองทาง:
   - แตะบัตร NFC ที่ด้านหลังเครื่อง แอปจะอ่าน UID แล้วยิง request ไปตรวจสอบสิทธิ์ทันที
   - กดปุ่ม **"เปิดประตู"** เพื่อสั่งเปิดประตูทันทีโดยไม่ต้องแตะบัตร
   - ทั้งสองทางแสดงผลเขียว (สำเร็จ) / แดง (ไม่สำเร็จ) บนหน้าจอเดียวกัน

⚠️ **ข้อควรระวังด้านความปลอดภัย**: ปุ่ม "เปิดประตู" ยิง request ทันทีโดยไม่มีการยืนยันตัวตนเพิ่มเติม
(ไม่มี PIN/biometric) ตามที่ระบุไว้ — ใครก็ตามที่มีแอปเครื่องนี้และไม่ได้ล็อกหน้าจอโทรศัพท์ไว้จะเปิด
ประตูได้ทันที หากต้องการเพิ่มความปลอดภัย แจ้งมาได้ จะเพิ่มขั้นตอนยืนยันตัวตนก่อนเปิดประตูให้

## API contract ที่แอปคาดหวัง

### ตรวจสอบสิทธิ์ (แตะบัตร)

แอปยิง `POST` ไปยัง **API Endpoint สำหรับตรวจสอบสิทธิ์** ด้วย body:

```json
{ "cardId": "04A1B2C3D4E5" }
```

`cardId` คือ UID ของบัตร (hex, ตัวพิมพ์ใหญ่, ไม่มี `:` คั่น) ตามที่อ่านได้จาก `Tag.id`

### เปิดประตู (กดปุ่ม)

แอปยิง `POST` ไปยัง **API Endpoint สำหรับเปิดประตู** ด้วย body ว่าง `{}`

### ทั้งสอง endpoint

หากตั้งค่า API Key ไว้ แอปจะแนบ header เดียวกันทั้งสอง endpoint:

```
Authorization: Bearer <API_KEY>
```

และคาดหวัง response กลับมาเป็น JSON รูปแบบเดียวกัน:

```json
{ "granted": true, "message": "เปิดประตูแล้ว" }
```

- `granted` (boolean, จำเป็น): `true` = สำเร็จ (แสดงผลเขียว), `false` = ไม่สำเร็จ (แสดงผลแดง)
- `message` (string, ไม่บังคับ): ข้อความที่จะแสดงแทนข้อความ default

ถ้ารูปแบบ request/response ของ API จริงของคุณต่างจากนี้ ให้แก้ที่
`app/src/main/java/com/nfckeycard/app/AccessApiClient.kt` — ฟังก์ชัน `buildVerifyBody` /
`buildOpenDoorBody` (ฝั่งส่ง) และ `parseResponse` (ฝั่งรับ) เท่านั้น ส่วนที่เหลือของแอปไม่ต้องแก้

## โครงสร้างโปรเจกต์

```
android-app/
├── app/src/main/java/com/nfckeycard/app/
│   ├── MainActivity.kt        # หน้าหลัก: จัดการ NFC + ปุ่มเปิดประตู + แสดงผล
│   ├── SettingsActivity.kt    # หน้าตั้งค่า endpoint ทั้งสอง / API key
│   ├── AccessApiClient.kt     # เรียก API ตรวจสอบสิทธิ์ / เปิดประตู
│   └── Prefs.kt               # เก็บค่าตั้งค่าใน SharedPreferences
├── app/src/main/res/          # layout, strings, ไอคอน
└── app/src/main/AndroidManifest.xml
```

## ข้อจำกัดที่ควรรู้

- ต้องทดสอบบนอุปกรณ์ Android จริงที่มีฮาร์ดแวร์ NFC (minSdk 24 / Android 7.0+) — Android Emulator
  ส่วนใหญ่ไม่มี NFC ให้จำลอง (ปุ่ม "เปิดประตู" ไม่ต้องใช้ NFC จึงทดสอบบน emulator ได้)
- โค้ดนี้ยังไม่ได้ผ่านการคอมไพล์จริงในสภาพแวดล้อมนี้ เพราะไม่มี Android SDK ติดตั้งอยู่
  (ตรวจสอบด้วย `gradle tasks` แล้วว่าไฟล์ Gradle ถูกต้องและ dependency ทั้งหมด resolve ได้)
  แนะนำให้เปิดใน Android Studio แล้วกด Run เพื่อ build จริงอีกครั้งก่อนใช้งาน
- ปัจจุบันรองรับ UID ของบัตรเท่านั้น (ไม่ได้อ่านข้อมูล NDEF บนบัตร) หากบัตรของคุณต้องอ่านข้อมูล
  อื่นเพิ่มเติม (เช่น sector data บน MIFARE Classic) แจ้งมาได้ จะเพิ่มให้
- ไม่รองรับการปลอมมือถือเป็นบัตร (HCE) เพราะเครื่องอ่าน UID-only ไม่รองรับกลไกนี้ (ดูคำอธิบายด้านบน)
