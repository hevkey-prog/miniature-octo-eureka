# miniature-octo-eureka

เว็บแอปเปิดประตูด้วยมือถือ (ไม่ต้องใช้บัตร) — เวอร์ชันเริ่มต้นแบบง่ายและเร็วที่สุด

## หลักการทำงาน

- ไม่ได้ทำให้มือถือ "ปลอมตัวเป็นบัตร NFC" (มือถือทั่วไปที่ไม่ได้ root ทำแบบนั้นกับเครื่องอ่านเดิมไม่ได้จริง ๆ)
- แทนที่ด้วยลิงก์ส่วนตัว (token) ที่เปิดครั้งเดียวบนมือถือ แล้วมีปุ่มใหญ่ ๆ กดเพื่อสั่งเปิดประตู
- ตอนนี้ยังไม่ได้ต่อกับฮาร์ดแวร์จริง (ไม่รู้ยี่ห้อ/รุ่นเครื่องอ่านหน้าประตู) จึงทำงานเป็น **โหมดจำลอง** — กดแล้วเห็นผลว่า "เปิดแล้ว" ในคอนโซล แต่ยังไม่สั่งกลอนประตูจริง

## วิธีรัน

```bash
node server.js
```

ไม่ต้องติดตั้งอะไรเพิ่ม (ใช้แค่ Node.js built-in modules) ตอนรันครั้งแรกจะพิมพ์ลิงก์ที่มี `?t=...` ออกมา — เปิดลิงก์นั้นบนมือถือครั้งเดียว ระบบจะจำ token ไว้ใน localStorage ของเบราว์เซอร์ให้อัตโนมัติ ครั้งต่อไปแค่เปิดหน้าเว็บแล้วกดปุ่มได้เลย

> หมายเหตุ: ถ้าจะเปิดจากมือถือจริง เซิร์ฟเวอร์ต้องอยู่ในเครือข่ายที่มือถือเข้าถึงได้ (เช่น Wi-Fi วงเดียวกัน แล้วใช้ IP เครื่องแทน localhost) หรือเปิดผ่าน tunnel เช่น `ngrok http 3000`

## เพิ่มผู้ใช้คนใหม่ (แจกลิงก์ให้มือถือเครื่องอื่น)

```bash
curl -X POST http://localhost:3000/api/enroll \
  -H "Content-Type: application/json" \
  -d '{"adminToken":"<token หลักที่ได้ตอนรันครั้งแรก>","label":"ชื่อคนที่จะให้สิทธิ์"}'
```

จะได้ token ใหม่กลับมา เอาไปต่อท้ายเป็น `http://<เซิร์ฟเวอร์>:3000/?t=<token ใหม่>` แล้วส่งให้เจ้าของมือถือเปิดครั้งเดียว

## ต่อกับฮาร์ดแวร์จริง (เมื่อรู้ว่ามีอุปกรณ์อะไร)

ตั้งค่า environment variable `DOOR_WEBHOOK_URL` ให้ชี้ไปยัง endpoint ที่สั่งเปิดกลอนประตูจริง (เช่น ESP32/relay ที่รับ HTTP POST แล้วสั่งเปิด):

```bash
DOOR_WEBHOOK_URL=http://<esp32-ip>/unlock node server.js
```

เมื่อกดปุ่มบนเว็บ เซิร์ฟเวอร์จะยิง POST ไปที่ URL นี้แทนการจำลอง

## ไฟล์สำคัญ

- `server.js` — backend (ตรวจ token, สั่งเปิดประตู, ออก token ใหม่)
- `public/index.html` — หน้าเว็บปุ่มเปิดประตูสำหรับมือถือ
- `data/tokens.json` — เก็บรายชื่อ token ที่ใช้ได้ (สร้างอัตโนมัติ ไม่ถูก commit เพราะเป็นข้อมูลลับ)

## ข้อควรระวัง

- `data/tokens.json` มี token ที่เทียบเท่ากุญแจเปิดประตู อย่า commit ขึ้น git และอย่าแชร์ต่อ
- ตอนนี้ยังไม่มี HTTPS ในตัว ถ้าจะใช้งานจริงนอกเครือข่ายบ้าน/ออฟฟิศ ควรมี reverse proxy ที่ทำ HTTPS ให้ (เช่น Caddy, Nginx) เพื่อไม่ให้ token หลุดระหว่างทาง
